# XHarness

Claude(Pro / Max)と ChatGPT(Plus / Pro)の**サブスクリプションの枠**をそのまま使う、Windows 向けのデスクトップ型コーディングエージェントです。
API キーは使いません。公式 CLI(`claude` / `codex`)でログインした資格情報を読み取って動きます。

- 作業フォルダのファイルを読み書きし、PowerShell でコマンドを実行します(実行前に確認します)
- Claude と GPT を会話の途中で切り替えたり、計画 → 実装 → レビューを分担させたりできます
- 各ステップ(モデルの呼び出し・ツール・確認)を画面に表示し、記録(レシート)を残します

> 個人利用を前提としたアプリです。コード署名はしていません。

---

## 同梱ファイル

| ファイル                     | 内容                                                                   |
| ---------------------------- | ---------------------------------------------------------------------- |
| `XHarness-Setup-<版>.exe`    | インストーラ版。スタートメニューに登録され、アンインストールもできます |
| `XHarness-<版>-portable.exe` | ポータブル版。インストール不要で、好きな場所に置いて起動できます       |
| `README.md`                  | このファイル                                                           |
| `SHA256SUMS.txt`             | 各ファイルのハッシュ値(改ざん確認用)                                   |

どちらか一方を使えば十分です。設定と履歴は同じ場所(後述の `%USERPROFILE%\.xharness`)に保存されるので、両方を使い分けても共有されます。

## 動作環境

### 必須

| 項目               | 内容                                                                                                                       |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| OS                 | Windows 10 / 11(64bit)                                                                                                     |
| サブスクリプション | Claude Pro / Max、または ChatGPT Plus / Pro(片方だけでも使えます)                                                          |
| 公式 CLI           | Claude を使うなら Claude Code(`claude`)、GPT を使うなら Codex CLI(`codex`)をインストール。ログインはアプリから開始できます |
| PowerShell 7       | コマンド実行(Bash ツール)に使います。`pwsh` が PATH にあること                                                             |
| ripgrep            | ファイル検索(Grep ツール)に使います。`rg` が PATH にあること                                                               |

### あると便利

| 項目    | 用途                                                       |
| ------- | ---------------------------------------------------------- |
| Git     | ブランチの表示、リポジトリを開く機能、作業の隔離(worktree) |
| Node.js | `npx` で起動する MCP サーバーを使う場合                    |

### 必要なものの入れ方(例)

PowerShell で次を実行します(winget の例)。

```powershell
winget install Microsoft.PowerShell
winget install BurntSushi.ripgrep.MSVC
winget install Git.Git
```

アプリ起動時、画面上部の「モデルの認証」で未認証・期限切れ・資格情報ありを確認できます。未認証や期限切れの場合は「認証・更新を許可」を選び、確認ダイアログで許可してください。公式CLIの画面とブラウザが開くので、ご自身でログイン・認可してください。完了後、アプリが資格情報を読み直します。キャンセル時は認証を行いません。

公式CLIを別に起動してログインした場合は「状態を再確認」を押してください。資格情報ありはファイルの確認結果で、提供元での有効性は送信時に確認します。認証中は会話を送信せず、会話終了後に認証を行ってください。認証完了後の依頼は自動再送信しません。

公式 CLI のログインは、それぞれの CLI の手順に従ってください。例:

```powershell
claude          # 初回起動時にブラウザでログイン
codex login     # ブラウザでログイン
```

ログイン後、資格情報は `%USERPROFILE%\.claude\.credentials.json` と `%USERPROFILE%\.codex\auth.json` に保存されます。
XHarness はこれらを**読むだけ**で、書き換えません。

## インストールと起動

### インストーラ版

1. `XHarness-Setup-<版>.exe` を実行します
2. 「Windows によって PC が保護されました」と表示されたら、**詳細情報 → 実行** を選びます(署名していないため表示されます)
3. インストール先を選んでインストールします(管理者権限は不要。ユーザーごとのインストールです)
4. スタートメニューの **XHarness** から起動します

アンインストールは「設定 → アプリ → インストールされているアプリ」から行います。設定と履歴(`%USERPROFILE%\.xharness`)は残ります。不要なら手で削除してください。

### ポータブル版

1. `XHarness-<版>-portable.exe` を任意のフォルダに置きます
2. ダブルクリックで起動します(初回は上と同じ SmartScreen の警告が出ます)

起動のたびに一時フォルダへ展開するため、インストーラ版より起動が少し遅くなります。

### 動作確認だけしたい場合(通信なし)

ショートカットのリンク先、またはコマンドラインで `--fake` を付けて起動すると、録画済みの応答で動きます。
サブスクの枠を使わず、資格情報も読みません。履歴は `%USERPROFILE%\.xharness-fake` に分けて保存されます。

```powershell
.\XHarness-<版>-portable.exe --fake
```

## 使い方

### 1. 作業フォルダを選ぶ

起動したら、タイトルバーのフォルダ名(または **Ctrl+O**)から作業フォルダを選び、新しいセッションを作ります。
リポジトリの URL を指定して開くこともできます。

初めてのフォルダで、そのフォルダの設定(`.xharness/config.yaml`)が権限を広げる内容を含む場合は、**信頼してよいか**を尋ねます。

### 2. 依頼を書く

画面下の入力欄(`❯`)に依頼を書いて **Enter** で送ります。改行は **Shift+Enter** です。
実行中は **Esc** で中断できます。

### 3. 確認に答える

ファイルの書き込みやコマンドの実行の前に、確認が表示されます。

| キー      | 意味                                               |
| --------- | -------------------------------------------------- |
| `y`       | 今回だけ許可                                       |
| `a`       | 常に許可(このフォルダに限って記録。次から聞かない) |
| `n` / Esc | 拒否                                               |

権限のモードは入力欄の右の切り替え(または **Shift+Tab**)で変えられます。

| モード        | 動作                                                   |
| ------------- | ------------------------------------------------------ |
| `default`     | 読み取りは確認なし。書き込みとコマンドは確認する       |
| `acceptEdits` | 作業フォルダ内の書き込みも確認なし(コマンドは確認する) |
| `plan`        | 読み取りだけ。書き込みはしない                         |

### 4. モデルを切り替える

入力欄の右のモデル名(または **Ctrl+M**)から選びます。会話の途中でも切り替えられます。
使用量(5時間枠・週間枠)は **Ctrl+U** で確認できます。

### キーボード操作

| キー      | 動作                         |
| --------- | ---------------------------- |
| Ctrl+N    | 新しいセッション             |
| Ctrl+W    | セッションを閉じる           |
| Ctrl+O    | 作業フォルダの選択           |
| Ctrl+B    | サイドバーの表示切り替え     |
| Ctrl+M    | モデルの切り替え             |
| Ctrl+U    | 使用量の表示                 |
| Ctrl+H    | ステップ表示(Hero)の切り替え |
| Shift+Tab | 権限モードの切り替え         |
| Esc       | 実行中の中断 / 確認の拒否    |

### 入力欄のコマンド

`/` から打ち始めると候補が出ます(Tab で入力)。

| コマンド                               | 動作                                                |
| -------------------------------------- | --------------------------------------------------- |
| `/model <プロバイダ:モデル> [effort]`  | モデルを切り替える(例: `/model claude:sonnet high`) |
| `/mode default\|acceptEdits\|plan`     | 権限モードを切り替える                              |
| `/compact`                             | 会話の履歴を要約して短くする                        |
| `/phase <段階>` / `/review`            | 計画 → 実装 → レビューの段階を手動で進める          |
| `/mcp`                                 | MCP サーバーの状態の表示と操作                      |
| `/mcp__<サーバー>__<プロンプト> 引数…` | MCP サーバーのプロンプトを使う                      |

### 計画 → 実装 → レビュー

大きめの依頼では、最初に計画を立てて画面で承認を求め、承認後に実装し、最後に別のモデルがレビューします。
動作は設定の `workflow.mode` で変えられます(`auto`: 必要なときだけ / `always`: 常に / `off`: 使わない)。

### Web 検索

モデルは必要に応じて Web 検索とページの取得を行います(初回は確認します)。
検索に使うプロバイダは、使用量の余裕に応じて自動で選びます。

### MCP サーバー(外部ツールの追加)

作業フォルダの直下に `.mcp.json` を置くと、MCP サーバーのツールを使えます(形式は Claude Code と同じ)。

```json
{
  "mcpServers": {
    "everything": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-everything"]
    },
    "remote": { "type": "http", "url": "https://example.com/mcp" }
  }
}
```

- サーバーは、**フォルダを信頼し、サーバーごとに承認した後**に起動します
- API キーなどは `.mcp.json` に直接書かず、`"${MY_TOKEN}"` のように環境変数で渡してください
- 認可が必要なサーバーは、既定のブラウザで認可します。トークンは Windows の暗号化(DPAPI)で保存します
- 状態の確認・再接続・承認の取り消し・ログアウトは `/mcp` から行えます

## 設定

設定ファイルは YAML です。無ければ既定値で動きます。

| 場所                                   | 対象                                                                 |
| -------------------------------------- | -------------------------------------------------------------------- |
| `%USERPROFILE%\.xharness\config.yaml`  | すべてのフォルダ                                                     |
| `<作業フォルダ>\.xharness\config.yaml` | そのフォルダだけ(権限を広げる項目は、フォルダを信頼したときだけ有効) |

主な項目の例:

```yaml
main:
  model: claude:opus # 既定のモデル
  effort: high # low | medium | high | xhigh | max
fallback:
  claude: codex:sol # Claude の枠が切れたら Codex で続ける
workflow:
  mode: auto # auto | always | off
web:
  enabled: true
  searchProvider: auto # auto | claude | codex
  maxSearchesPerSession: 100
mcp:
  enabled: true
permissions:
  rules:
    - { tool: Bash, pattern: "git status*", decision: allow }
context:
  compactThreshold: 0.8 # コンテキストの 80% で自動的に要約する
  memoryFiles: [AGENTS.md, CLAUDE.md] # 作業フォルダの指示ファイル
```

不正な値は既定値のまま使い、起動時に警告を表示します。

### 起動オプション

| オプション                             | 内容                                   |
| -------------------------------------- | -------------------------------------- |
| `--fake`                               | 通信なしの動作確認モード               |
| `--model <モデル>` / `--effort <段階>` | 起動時のモデル・effort                 |
| `--resume <セッションID>`              | 前のセッションを開いて起動             |
| `--devtools`                           | 診断用に開発者ツールを使えるようにする |

環境変数 `XHARNESS_HOME` を設定すると、設定と履歴の保存場所を変えられます。

## データの保存場所

| 場所                                | 内容                                                 |
| ----------------------------------- | ---------------------------------------------------- |
| `%USERPROFILE%\.xharness\`          | 設定・セッション履歴・レシート・「常に許可」のルール |
| `%USERPROFILE%\.xharness\secrets\`  | MCP の認可トークン(暗号化済み)                       |
| `%USERPROFILE%\.xharness\logs\mcp\` | MCP サーバーのログ(秘密値はマスク)                   |

XHarness はアクセストークンをログ・画面・記録に出しません。必要なときは先頭6文字だけを表示します。

## 困ったとき

| 症状                                 | 対処                                                                                                                          |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| 「ログインが必要」などのエラーになる | 公式 CLI(`claude` / `codex`)を一度起動して、ログインし直してください。期限切れのトークンの更新は公式 CLI に任せています       |
| コマンドが実行できない               | PowerShell 7(`pwsh`)が PATH にあるか確認してください                                                                          |
| ファイル検索ができない               | ripgrep(`rg`)が PATH にあるか確認してください                                                                                 |
| 使用量の上限に達した                 | 5時間枠・週間枠が回復するまで待つか、`/model` で別のプロバイダに切り替えてください(`fallback` の設定で自動切り替えもできます) |
| MCP サーバーにつながらない           | `/mcp` で理由を確認してください。詳しくは `%USERPROFILE%\.xharness\logs\mcp\` のログを見てください                            |
| 起動時に SmartScreen の警告が出る    | 未署名のためです。「詳細情報 → 実行」で起動できます                                                                           |

---

## 注意事項

- 非公開のエンドポイントを使っているため、提供元の仕様変更で動かなくなることがあります
- 使用量はサブスクリプションの枠から差し引かれます
- 自動アップデートはありません。新しい版はファイルを置き換えて使ってください(設定と履歴は引き継がれます)

## 学習用HTMLレポート

会話の実行終了後、receipts の「HTML出力」で保存先を選びます。保存したHTMLはブラウザで読めます。各「#」の見出しをクリックすると、その処理の入力・出力・詳細を個別に開閉できます。LLM呼び出しだけ紫で表示し、STEP・ツール・子エージェントへの委託も開始順に確認できます。

出力時のLLM通信はありません。レポートには会話とソースコードが含まれます。通信なしで動作確認した場合は「LLM模擬・実通信なし」と表示します。
