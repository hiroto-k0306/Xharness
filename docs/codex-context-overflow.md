## 修正（ユーザー承認済み）

`src/main/context/provider-compactor.ts` の Codex 境界選択だけを変更。

- 通常は直近2ターンを保持する。
- 保持末尾が圧縮閾値から overhead と要約領域を引いた容量に収まらないとき、ターン内の安全なメッセージ境界へ対象を広げる。初回の長いターンも対象。
- 未解決の tool_use ID を追跡し、全結果が揃った境界だけを使う。並列呼び出しと分割して届く結果も組を分割しない。不整合なIDでは境界を進めない。
- 最新のメッセージ／ツール組と未解決の呼び出しを残す。残す末尾の目標は利用可能容量の半分とし、繰り返しの圧縮を避ける。目標を満たす境界がない場合は最も先の安全な境界を使い、最終的な fits 判定で停止を判断する。
- 要約は既存の Luna 呼び出し（固定 system、tools なし、reasoning・compaction除外）を使う。要約の最大16,000 UTF-16単位がJSON内で最大6バイトにエスケープされる場合も考え、ラッパー込み32,064推定トークンを予約する。実際の fits は取得した要約から再計算する。
- 前回の要約を引き継ぎ、チェックポイントを前進させる。失敗時は旧チェックポイントを保持し、同一ターン内で再試行しない既存ルールを維持する。
- Claude の境界・署名付きサーバー圧縮、offline の決定的圧縮、system/tools、保存履歴は変更しない。
