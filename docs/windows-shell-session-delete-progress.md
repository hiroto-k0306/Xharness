# PowerShell検出とセッション削除

2026-10-04。ブランチ: `codex/windows-shell-session-delete`。

## PowerShellの誤検出

- ユーザーのWindowsApps版 `pwsh.exe` は `access()` に成功する一方、
  `stat()` が `EACCES` になることを実測した。従来の検出はこれを
  「PowerShellが存在しない」と扱っていた。
- WindowsApps内の実行エイリアスに限定して、この組み合わせを検出可能にした。
  一般の権限エラーやディレクトリは実行ファイルと扱わない。
- PATHに加え、PowerShellだけはユーザーのWindowsAppsと
  ProgramFilesのPowerShell/7を探索する。古いPATHを継承したアプリにも対応。
  システム全体のPATHは変更しない。
- Bashの前景・背景実行と認証CLI起動は、検出した絶対パスを使用する。
  認証CLIの子プロセスには選択したPowerShellのディレクトリを渡す。
  認証方式そのものは変更しない。
- 検証環境: Node 24.16.0、ユーザーの
  `C:/Users/ahwri/AppData/Local/Microsoft/WindowsApps/pwsh.exe`、PowerShell 7.6.6。
- PATHを空にしたBashで固定の `Write-Output` が成功。
  認証テストはダミーClaude/Codexコマンドを使い、実CLI・認証・モデル通信は行わない。
- rg不在時の表示は検索不能のエラーではなく、Node代替検索への切り替え通知。
  代替検索は維持する。
- 関連8ファイル84テスト成功（UIの削除確認、H3背景シェル、送信・削除競合を含む）。

## セッション削除

- 一覧の各セッションに削除ボタンを追加する。実行中・権限待ちは無効。
- 確認画面で対象と削除内容を表示し、キャンセルでは保存処理を呼ばない。
- 既存の `delete_session` を利用し、履歴・チェックポイント・LLM通信記録を削除する。
  main側の排他制御と保存復活の防止処理は維持する。
- worktreeと作業ファイルは残す。片付けが必要ならキャンセルして、
  対象セッションの既存worktree操作を先に行うことを確認画面に表示する。
- 削除成功時は画面のキャッシュも除去。失敗時は確認画面に通知する。
