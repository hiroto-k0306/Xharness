# 通常作業のフロー単位の許可

対象ブランチ: feature/native-workflow-boundary。変更前HEAD: d3f01d95383e1c9332dfd302408b59a5de2e39ae。Windows / Node 24.16.0で関連オフライン検証を実施。現行仕様: SPEC §15「通常作業の公式ツール探索」。2026-10-09の利用者の直接依頼を仕様変更の承認として扱った。

## 調査と変更

直近の保存記録は質問判別成功、計画成功（69,130 ms）、実装timeout（674,351 ms）。通信確認3回でレビューは未実施。実行上限120秒と、承認待ち中のタイマー停止が実装されている。経過時間だけから、各承認の待機時間やSDK内の遅延を特定したとは扱わない。今回タイムアウト値は変更していない。表示には承認待ちが制限時間から除かれることを追加した。

- 通常作業の操作確認に「このフローのみ許可」を追加。現在のworkflow・操作ID・digest・期限が一致し、計画承認済みの通常作業である場合に限って受理する。
- 自動モード（内部acceptEdits）は計画承認後にフロー単位の操作許可を有効化する。計画を自動承認しない。通常モードの個別許可・拒否も維持する。
- セッション側で選択した有効モードをmainから渡す。セッションのplanが全体設定の自動モードより優先する。
- フロー許可はそのworkflowとcwdに限るメモリ内の状態。終了・停止・再起動で失効し、ディスクには保存しない。固定評価課題へ適用しない。
- 公式sandbox、readonly工程、禁止対象、操作要求の整合・変更・重複検査は維持する。複合shellを安全な読み取りと判定し直したり、OS権限を緩和したりしない。停止後に自動再送しない。
