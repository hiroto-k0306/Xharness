# 公式workflowの計画モデルをメインモデルに変更（2026-10-07）

## 仕様

- 計画モデルは、タスク開始時に利用者が選択中のメインモデル（`provider:alias` または完全ID）とeffort。
  - パネルが作成コマンドに含めて送る。
  - `resolveModel` とカタログで完全IDに対応付け、そのモデルの公式接続（Claude SDK／Codex App Server）の一覧と照合する。
- 使えない場合は `計画モデル…` で始まる理由を表示して停止し、別モデルへは切り替えない。使えない場合とは次のとおり。
  - 対応付けできない
  - 一覧にない
  - 通常枠を確認できない
  - effortに対応していない
- 製品の新規タスクで選択がない場合も停止し、従来のOpusへは戻さない。
- 確定した計画モデル（provider・完全ID・effort・選択値）は、runtimeが記録の `planner` に保存する。再開は記録したものを使い、実行中の選択変更は次のタスクから反映する。
- Claude・Codexのどちらが計画しても、計画phaseは読み取り専用で、同じ出力スキーマ・検証・利用者承認を通す。空や無効な計画は1回で停止し、再試行しない。
- 計画は課題ごとに、通常枠で使える公式モデル全体から実装担当とレビュー担当を選ぶ。
  - レビュー担当は新しい計画では必須で、実装担当と同じ会社なら計画を拒否する（`reviewer-same-provider`）。
  - 計画前に、両社のモデルが1つ以上使えることを確認する。
- 変えていないもの：「質問だけ送信」の経路、合成課題の実装先指定（パネルの「実装候補」はテスト用の足場として維持）。

## 追加：質問用モデルを完全IDで固定（2026-10-07）

修正前は、質問の宛先モデルが一覧の順番に左右されていた。

- Codex側：一覧で最初に見つかった利用可能なモデルを選んでいた。
- Claude側：名前にhaikuを含む最初のモデルを選んでいた。

このため、画面に表示するLuna/Haikuと、実際に選ばれるモデルが一致しない可能性があった。

### 修正

- `src/shared/official-workflow.ts` の `QUESTION_MODELS`（Claude `claude-haiku-4-5-20251001`、Codex `gpt-6-luna`、いずれも `catalog/models.yaml` の完全ID）を、serviceの選択とパネルの表示の両方が参照する。
- 公式接続の一覧で、このIDと完全に一致するものだけを使う。同じ会社の別モデルにも切り替えない。使えない場合は次の理由を表示して停止する。
  - 一覧にない：`…一覧にありません`
  - 一覧にあるが使えない、または通常枠を確認できない：`…を利用できないか、通常枠を確認できません`
- 模擬モードは従来どおりfixtureのモデルを使い、画面には「模擬モデル」と表示する。

### テスト（変更箇所）

`service.test.ts` に7件、`OfficialWorkflowPanel.test.tsx` に2件を追加した。

- 一覧順に依存しない：両社とも、対象モデルが一覧の先頭でも末尾でも同じ完全IDが選ばれる。記録の `requestedModel` もそのIDになる。
- Lunaがない場合：一覧にない、または一覧にあるが通常枠が不明なとき、理由を表示して停止する。モデルは呼ばない。
- 表示と選択の一致：パネルの質問先表示が両社とも `QUESTION_MODELS` の値で、送信先もその会社になる。
- 2つの完全IDが、同梱カタログに有効なモデルとして存在する。
