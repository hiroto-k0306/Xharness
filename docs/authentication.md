# 初回認証・期限切れの案内

2026-10-02、ユーザー承認で追加。DESIGN.md §14.1。

## 使い方

起動時に画面上部の「モデルの認証」でClaude/Codexの状態を確認する。

- 未認証・期限切れ・再認証が必要：対象の「認証・更新を許可」を選ぶ。
- 確認ダイアログで許可すると、公式CLIの画面が開く。ブラウザのログイン・認可はユーザーが行う。
- 完了後、アプリが資格情報を再読み込みする。依頼は自動再送信しない。
- キャンセルではCLIを起動しない。会話実行中・認証中は認証を重複して開始しない。
- 外部でCLIを使ってログインした場合は「状態を再確認」を押す。

「資格情報あり」はファイルの確認結果で、提供元での有効性は送信時に確認する。ClaudeのexpiresAt、CodexのJWTのexpがある場合に期限を確認する。期限が読み取れない資格情報を、提供元で認証済みとは表示しない。

認証は公式CLIの `claude auth login --claudeai` / `codex login` を使う。手元のCLIヘルプで確認した引数。PowerShell 7と対象CLIのインストールが必要。自前refresh、資格情報の編集やコピーは行わない。CLI出力はアプリのログ・IPCへ転送しない。更新前後の秘密値をメモリ内のマスク対象に保持し、画面やレシートへ出さない。`--fake`では資格情報確認・認証操作を行わない。

## 検証

Windows、Node.js 22。実API通信なし。

最終確認は全体82ファイル・669件成功（maxWorkers=4）。初回の通常並列実行では既存headless-replayの1件が5秒でタイムアウトしたため、単独4件の成功と、並列数を抑えた全体成功を確認した。ネイティブ確認・実行中の拒否・提供元の認証拒否・未認証時の手動圧縮拒否も含め、関連6ファイル・19件成功。型チェック・lint・Electron/headlessビルドを確認。

- 未認証・不正JSON・期限切れ・有効期限内・期限不明のローカル状態。元ファイルを変更せず、トークン・アカウントIDを状態に含めない。
- 起動時にCLIを実行しないこと、許可前の起動防止、キャンセル、二重起動、認証中の状態競合、固定メッセージでの失敗・再試行。
- ネイティブ確認はキャンセルを既定にし、明示的な許可ボタンだけを承認とする。
- 認証前の送信拒否、会話実行中の認証拒否、更新した秘密値のマスク、提供元の認証拒否を状態へ反映。FakeProviderで通信なしで確認。
- 隔離したPATHと模擬CLIを使い、WindowsのPowerShell経由で両プロバイダの固定引数が渡ることを確認。実CLIやユーザーの資格情報は変更していない。
- 画面部品の状態・承認操作・再確認・実行中の無効化・エラー表示。

インストーラ・portableを作成。実画面の取得は、ユーザーの利用承認後もcomputer-useの自動承認レビューがXHarnessを利用未承認として拒否したため未確認。実際のブラウザログイン・資格情報更新・更新後の実API通信は未実施。
