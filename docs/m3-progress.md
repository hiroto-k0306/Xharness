## 実装と設定

- ユーザーの `~/.xharness/config.yaml` に `limits: {llmCallsPerTurn: 0, llmCallsPerSession: 0}`。0は無制限で、未設定も0。0以上の安全な整数だけ受け付ける。プロジェクトの設定ではユーザーの上限を変更できない。
- Claude / CodexのAdapterで、変換・認証が成功した後、fetch直前に試行回数を加算する。429・HTTPエラー・送信後の切断・通信例外も数える。変換や資格情報読み込みの失敗、既に中断済みの要求、上限で拒否した要求は数えない。プロバイダの課金の確定回数を表す値ではない。
- AsyncLocalStorageで親ターンのカウンターを共有する。通常応答・再試行・フォールバック・自動圧縮・ワークフローの各段階・子エージェント・Web要約も同じ上限に従う。並列の子でも送信前の判定と加算は同期的に行い、上限を超えて予約しない。通信トレースの有効・無効に依存しない。
- 上限NならN回目の送信は許可し、次の送信を拒否した時点で親のAbortControllerを中断する。理由は `budget_exceeded`。親・実行中の子を停止し、履歴を保存して入力を待つ。ターン上限は次の入力で0から数え、セッション上限は新規セッションまたは設定変更まで維持する。
- `sessions/<id>.llm-calls.json` に回数・模擬の内訳・上限・計測開始時刻を保存する。一時ファイル＋renameで送信ごとに順番に保存し、次のターンに移る前に完了を待つ。計測は導入時からで、過去の履歴から推定しない。再起動・会話の巻き戻し・モデル変更では累計を減らさない。セッション削除ではカウンターも削除する。
- 保存先を送信前に確認する。読めない／不正なカウンターを0に戻さず `budget_storage_failed` で停止し、秘密値や低水準の例外文を出さない。送信後の保存失敗も親を中断する。
- 手動 `/compact` を独立した1ターンとして計測する。上限で拒否された場合は元の履歴を維持し、停止理由が後続のidle通知で消えないようにした。headlessにも同じ計測・制限・保存を組み込んだ。
- UsagePopoverで今ターン／セッションの「回数 / 上限」を表示する。0は「無制限」。FakeProviderの試行も制限確認に使用し、「うち模擬」を明示する。サブスク枠の残量と通信回数は別に表示し、既存のヘッダに基づく警告は維持する。

既定値の確認：[Claude Code公式CLI資料](https://code.claude.com/docs/en/cli-reference)（2026-10-03）。`--max-turns`は既定無制限、金額上限は指定時に有効で子の使用額も含む。XHarnessでは仕様どおり回数を制限し、ドル換算は実装しない。
