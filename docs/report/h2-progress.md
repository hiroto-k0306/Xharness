# H2：環境診断とエラーの構造化

2026-10-02。DESIGN.md §26 の指定順序に従い、H2だけを実装。ブランチは `codex/h2-environment-diagnostics`、開始点は `design/section-26` の `db1af06`。H1以降は未着手。

## 実装

- セッションの最初のLLM通信前に、PATH上のrg / pwsh / git、作業フォルダの存在・一覧取得・書き込みを診断。書き込みは一意の空の一時ファイルを作成・閉じて削除し、作業ファイル・Git設定を変更しない。結果は固定の日本語の警告で表示する。
- 診断結果をセッション索引へ保存し、短い一文だけsystemへ追加。後のターン・アプリ再起動による再開でも診断文を変えない。既存履歴に診断がなければ最初の使用時に作成する。子とheadlessにも同じ診断を適用。
- rgがなければGrep / GlobをNode検索へ切り替える。ツール名・引数・集合を変えず、権限gateは維持。`.gitignore`は入れ子・否定パターンを含めて適用し、検索先の親のルールも読む。Grepの明示したファイルはignoreを回避できるが、資格情報・鍵の除外は回避できない。隠しエントリ・バイナリ・再帰のシンボリックリンクを除外する。
- Grepは両方式で250件まで。対象を絞るための打ち切り表示を付ける。Node検索はJavaScriptの正規表現を使い、使えない形式は固定の`invalid_args`を返す。正規表現はWorkerで実行し、重いパターンでも中断・時間切れで終了できる。
- ツール出力に`error: {kind, message}`を追加。種別は`missing_cli / not_found / denied / timeout / aborted / invalid_args / failed`。例外の生メッセージ・PATH・プロセス引数を診断へ転送しない。引数やフックの固定の詳細説明は、従来どおり秘密値のマスクを通して返す。
- LLMへ返す失敗結果には構造化した種別・固定の日本語メッセージを付ける。親・子のレシートにもerrorを保存し、要約へ種別を出す。既存履歴にはerrorがなくても読める。
- 同じツール・同じ種別の失敗が当該ツールの呼び出しで3回続くと`awaiting_user`で止め、理由と確認の依頼を会話に表示する。成功や種別変更でカウントをリセットし、次のターンには持ち越さない。他のツールの成功だけでは当該ツールのカウントを消さない。未レビューの変更は完了にしない。従来の全体の連続エラー上限も維持。

## 手元で実施が必要・未確認

- 実インストール版の画面で環境警告を確認。exeは今回の実装単位では作成していない。
- 実Windows ACLによるフォルダの一覧取得拒否・書き込み拒否。診断は起動時の一時点の結果で、以後のACL変更は各ツール実行時のエラーで扱う。
- PATHのCLI有無はファイルと実行権限で確認し、CLI自身の正常動作・バージョンまでは診断しない。壊れたCLIの実行失敗は`failed`で返す。

## 公式資料の確認

[Claude Codeの公式ツール資料](https://code.claude.com/docs/en/tools-reference#grep-tool-behavior)で、Grepの`.gitignore`尊重と、Globが既定では尊重しないことを確認した（2026-10-02）。Grepの250件上限は同資料には見つからなかった。XHarnessではユーザーの仕様指定を維持し、両方式のignore尊重・250件を独自の規定としてDESIGN.mdに明記した。`.gitignore`の解析には既存依存ツリーにもあったignore 7.0.11を直接依存に追加した。
