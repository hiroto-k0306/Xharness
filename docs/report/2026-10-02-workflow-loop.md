# バグ報告：提案・停止依頼で実装要求を繰り返す

記録日：2026-10-02。Windowsのインストール版で発生。修正方針はユーザー承認済み。

## 確認した事象

対象はローカルセッションb8191148。「このアプリ自信の修正案を考えてください」という依頼を、D:\AIwork\testで実行していた。ログを読み取っただけで、調査のための実API通信は実行していない。

- 20:27:27〜20:28:26：LLM通信13回。Bashは拒否、Glob/Grep/Readは失敗。モデルが提案のみ・変更なしと回答しても、ハーネスが計画・実装・レビューを要求した。SkipPlanの結果は「Implement a small fix. RequestReview remains required.」。差分のないRequestReviewは拒否された。
- 20:29:39〜20:30:26：「一旦停止して」にモデルが停止を回答したが、ハーネスが継続指示を24回挿入し、LLM通信25回（最後は中断）が発生。ツールの実行は0件だった。
- Glob/Grep/Readの失敗は「Tool execution failed」のみで、原因が区別できなかった。

根拠：~/.xharness/sessions/b8191148.jsonl、receipts/b8191148.jsonl、traces/b8191148.000002.jsonl、traces/b8191148.000003.jsonl。時刻は日本時間。ローカルの通信ログ・履歴・署名・資格情報はこの報告書やリポジトリへコピーしていない。

## 原因

1. WorkflowRuntimeはBashの保守的な権限判定のdenyも書き込み意図として扱い、読み取り調査でもclassifyからplanへ移行していた。
2. SkipPlanは常にimplementへ移行し、end_turn後に計画項目も差分もない状態でレビュー成功を要求した。提案だけ・実装できない状態の終了経路がなかった。
3. 継続指示に進展の検査がなく、モデルの停止回答にも同じ指示を返した。自然言語の停止は通常のモデル入力として処理されていた。
4. coreのcatchがエラーを共通文言に置き換え、runProcessも起動失敗の種類を捨てていた。通常のWindows PATHにはrgがなく、対象フォルダにREADME.md/package.jsonも存在しないことを別途確認した。権限拒否とこれらの失敗は別の原因である。

## 影響

ユーザーの相談範囲を超えて実装を要求し、進展のないLLM通信でサブスク使用量と待ち時間を消費する。画面に失敗の対処方法が出ず、モデルも同じ探索を繰り返す。

## 修正

- 拒否されたBashだけでは実装段階を開始しない。
- autoで計画項目・差分のない提案はend_turnで終了。次の依頼で再判定する。変更のある実装にはレビューを必須とする。
- 同一の作業状態でend_turnが3回続けばworkflow_stalledで停止。段階・項目状態・レビュー回数・差分が変わった場合は繰り返し回数をリセットする。
- 停止ボタン・/stop・限定した単独の停止指示はローカルで中断し、LLMへ送らない。承認待ちも解除する。
- CLI不足・ファイル不存在・アクセス拒否・時間切れ・中断を固定の日本語で区別する。例外や秘密値は転送しない。

## 検証

Windows・Node.js 22で全体83ファイル688件成功（maxWorkers=4）。型チェック・lint・Electron/headlessビルド成功。FakeProviderと隔離した一時フォルダで、提案の終了、SkipPlan後の変更なし終了、次の実装依頼のレビュー、進展のない継続指示の停止、/stopと「一旦停止して」による承認待ちの中断、CLI不足とファイル不存在の安全な表示を確認した。停止ボタンは承認待ちで入力欄が無効でも押せることを画面部品のテストで確認した。実APIでの再現試験は行っていない。

実CLIの導入（rgなど）は本修正では行わない。対象フォルダ・ツール不足の解消はユーザー側で必要。実アプリの変更後の試用結果は別途確認する。

## 追加対応：明示的な停止・質問ツール

2026-10-02、ユーザー承認によりClaude / Codex共通のStopTaskとAskUserQuestionを追加。LLMがツールで停止・質問を要求した場合は継続指示を挿入せず、同じ応答に含まれる他の操作もキャンセルする。未完了レビューは維持する。子エージェントの停止・返答待ちも完了扱いにせず親へ返す。詳細と検証結果は[共通ツールの説明](../../Old/doc-layout-0e5fa40/docs/agent-tools.md)を参照。自然言語の停止語の推測で強制停止する処理は追加していない。
