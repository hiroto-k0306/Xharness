# Codex ストリーム内過負荷エラーの復旧

## 原因（2026-10-04 確認）

画面の `Codex stream returned an error` / `リクエストが拒否されました` について、既存のローカル保存済み Codex トレースを調べた。新規の実 API 試験・資格情報の読取は行っていない。

確認した 5 件はいずれも SSE `error` イベントの `data.error` に以下を含んでいた。

- `type: service_unavailable_error`
- `code: server_is_overloaded`
- `headers` に `x-retry-metadata` が存在（値の意味は未検証、再試行判断には使わない）

旧実装はこのエラーを一律に `kind: request, retryable: false` へ変換していた。その結果、一時的なサーバー過負荷なのに「リクエストが拒否されました」と表示し、その場で停止していた。

実測した type / code を保持し、本文を置換、ヘッダと他のフィールドを削除した最小 fixture を `test/fixtures/codex/stream-error.json` に保存した。リクエスト・資格情報は含めない。

## 修正範囲

DESIGN.md §6 / §7 の Adapter 境界と既存の Agent Loop の再試行方針を維持する。変更は Codex の SSE 変換と、失敗したモデル試行の未確定表示の破棄。

- 上記の **type と code が両方一致**する場合だけ、再試行可能な `transport` エラーへ変換する。本文は固定の「Codex側が一時的に混雑しています」。生の本文・ヘッダ・任意のエラーコードは ProviderEvent へ渡さない。
- 既存の Agent Loop により、1秒・2秒・4秒待って最大3回再試行する（初回込み最大4送信）。上限・キャンセル・通信予算・権限の仕組みは変更しない。
- それ以外のストリーム内エラーは未分類の `protocol` エラーとして停止する。未知の原因を「リクエスト拒否」と断定せず、同じ送信を繰り返さない。
- HTTP 401 / 403 の認証エラー、400 の入力エラーなどの既存の非再試行処理は維持する。新たな公式 CLI 起動・自前 refresh は追加しない。
- `response.failed` の `response.error` に同じ type / code が来た場合も対応する。この envelope は実測済みではなく、記録されたエラーのフィールドを使う合成テストで確認した。`response` の欠損・不正な形も例外にせず、非再試行の `protocol` イベントを返すことを decoder の直接テスト7件で確認した。

レビュー対応として、失敗試行の途中テキスト・未実行ツールカード・対応表・未送信テキストバッファを破棄する処理も追加した。既存の main → renderer イベント経路へ `attempt_discarded` を追加し、セッション ID / メッセージ ID / カード ID で未確定表示だけを削除する。別セッション、確定済みの履歴・ツールカード、保存レシートは維持する。これは本番の復旧表示用イベントであり、新しい command やテスト専用 IPC は追加しない。

これはすべての障害を無条件に自動修復する変更ではない。過負荷が続けば再試行上限で停止する。他モデルへの過負荷 fallback は追加していない。

## 確認

最新版で、Node 22.23.3 の関連 **10ファイル / 94件**が成功。Node 24.16.0 の全体は **143ファイル / 1366件**成功（今回の新規テストは22件 + 4件 = 26件）。`typecheck`、`lint`、`build`、変更コードの Prettier 検査、`git diff --check` も成功。Node / pnpm / Store版 PowerShell の版・実体は [GUI検証時の環境表](gui-testing.md#windows-実測2026-10-04) と同じ。GUI文書の1340件は、この修正前の記録。

新規テストは、実録の過負荷分類、本文・ヘッダ非漏えい、未知・認証風・不正形の非再試行、同一履歴での復旧、失敗応答内のツール未実行と成功後の実行1回、再試行上限、待機中のキャンセル、HTTP 400 / 401 / 403 の非再試行を確認する。成功側には既存の Phase 0 実録を利用する。さらに4件の Loop → TurnEvents → renderer reducer テストで、失敗カードの削除と再試行成功カードへの結果対応、途中テキストの重複防止、バッファだけの失敗、別セッション・確定済み履歴の保全、429 fallback 時の破棄、同イベントを renderer → main command に転用できないことを確認する。

最終失敗でも未確定の途中出力と未実行カードは破棄する意図。4件目のテストで、再試行されず、過去の確定履歴・カード、エラー通知、保存レシートが残ることを確認する。

全体試験の最終確認は 2026-10-04T16:12:46Z 終了。別の suite やレビューを同時実行せず、foreground で以下を実行した（exit 0、173.59秒）。

```powershell
.\scripts\pnpm.ps1 exec 'C:\Program Files\nodejs\node.exe' node_modules/vitest/vitest.mjs run --exclude=spike/.out/** --exclude=.tools/** --exclude=dist/** --maxWorkers=1 --testTimeout=30000
```

レビュー側の標準の並列実行は、既存の PowerShell / Git 系でタイムアウト等の失敗があり、2回とも全体成功しなかった。上記は、同時実行なし・直列・30秒制限での成功であり、標準の並列実行の安定化を意味しない。AskUserQuestion の既存 React 重複 key 警告も未対応。

今回の修正を実際の混雑中のサービスへ再送信して確認する試験は未実施。
