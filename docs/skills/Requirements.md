# スキル利用の要件定義

## 背景と目的

利用者がプロジェクト内の手順や知識を確認し、必要な版を明示して作業へ利用できるようにする。利用方法は、通常会話へ非信頼の参考資料を送る操作と、公式基盤のスキル機構へ選択したスキルを渡す操作に分かれる。参考資料を送信しただけでスキルを実行・登録したと表示しない。

この領域の検証可能な契約は [Spec.md](Spec.md)、実現方法は [Architecture.md](design/Architecture.md) を正本とする。基準は `0e5fa40`、2026-10-09 のコード読取。過去の検証記録は当時の結果であり、最新実機成功の代用にしない。

## ステークホルダー

| 対象                 | 必要とすること                                                            |
| -------------------- | ------------------------------------------------------------------------- |
| 作業を依頼する利用者 | 出典・版・対応状況を確認して選択し、読取許可と作業承認を保持する          |
| プロジェクト所有者   | 登録範囲外の読取や、本文による権限拡大・永続設定変更を防ぐ                |
| 履歴を確認する利用者 | 選択、公式機構への受渡し、観測された呼出状態を区別する                    |
| 実装・検証の担当者   | GUIとheadlessの共通サービス、providerごとの能力差、限定検証の根拠を追える |

## 利用者の意図

利用者は、提供されたスキルの出典と版を理解したうえで、必要な知識を作業へ利用したい。資料として参照する場合と、公式基盤のスキル機構を使う場合を自分で選び、利用可能な範囲と停止理由を把握できることが必要である。

提供元やproviderによる能力差があっても、対応していない操作を成功として扱わない。資料の一部や設定を黙って捨てて目的を達成したように見せず、利用者が確認した版と実際に使用する版の関係を保つ。具体的な対応状況・対象・上限・振舞いは [スキル仕様](Spec.md) で定義する。

## 前提と制約

- GUIとheadlessは共通の公式実行基盤を利用する。手動の資料管理とモデルによるスキル利用は異なる入口として扱う。
- ローカル資料の利用は、登録したプロジェクト・保存会話・利用者領域の所有範囲と既存の許可確認を前提とする。
- 利用者が確認した出典と版の選択を尊重する。資料の更新やproviderの違いを、別版・別の利用方法への同意と解釈しない。
- 公式基盤への接続は、スキルの作成者・監修者による認定や本文の安全性の保証を意味しない。
- メモリ、通常作業の承認、DAGやモデル選択の共通仕様はそれぞれの領域で定義し、ここで再定義しない。

## 非機能要件の概要

安全性は、所有範囲・出典・既存権限の維持と秘密の保護を要求する。再現性は、選択した版と使用する版を追跡でき、過去の記録が保持されることを要求する。観測性は、要求・受渡し・確認できた使用状態を区別し、欠測を成功で補わないことを要求する。資源制限は、資料の規模に上限を設け、その制約が利用者の意図を黙って変更しないことを要求する。具体的な条件は仕様に集約する。
