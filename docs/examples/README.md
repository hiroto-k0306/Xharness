# フックとGitコマンドの設定例（L1・L2）

DESIGN.md §26.3 のLow項目のサンプルです。ファイルを置いただけでは有効になりません。公式Claude Codeの設定形式ではなく、XHarnessの既存STEPフック（§19.10）とユーザー定義コマンド（M2）を使います。

## L1：操作前のブロック・編集後のフォーマット

[hooks.yaml](hooks.yaml) の `hooks` 配列を、対象プロジェクトの `.xharness/config.yaml` に統合してください。既存の設定・フックは上書きせず残します。プロジェクトのフックは一覧を確認して承認したときだけ動きます。全プロジェクトに適用したい場合は、内容を確認したうえでユーザーの `~/.xharness/config.yaml` に設定できますが、こちらはプロジェクトフックの承認対象ではありません。

- `protect-migrations` は `before:act` で Edit / Write / MultiEdit の `migrations/**` をブロックします。Claude CodeのPreToolUseに相当する用途の例です。Bash、外部アプリ、ファイルシステム全体を制限するものではありません。1バッチ内に対象操作がある場合は、そのSTEPのほかの操作もブロックされます。
- `format-typescript` は `after:act` で `src/**/*.ts` / `src/**/*.tsx` の候補をローカルのPrettierに渡します。対象プロジェクトにPrettierが既に必要です。コマンドはダウンロードやインストールを行わず、存在しなければ固定エラーを返します。`{{files}}` はXHarnessがPowerShellの引用済み引数に展開するため、自分で引用符を重ねません。終了コードが非0なら `onFailure: inject` によって失敗内容をモデルに返します。

フックは操作の成否ではなく、STEPと呼び出しの条件に一致して動きます。操作が失敗した場合でも一致した既存ファイルがフォーマットされる可能性があります。フォーマッターによる変更は外部コマンドの変更なので、ファイルツールのチェックポイントに自動で追加されません。次のEdit前にReadで読み直し、差分を確認してください。巻き戻し時には外部変更との不一致で対象が除外される場合があります。

## L2：コミット・PRの提案コマンド

[commands/commit.md](commands/commit.md) と [commands/pr.md](commands/pr.md) を、必要なものだけ `<project>/.xharness/commands/` にコピーしてください。プロジェクトを信頼すると `/commit` と `/pr` が一覧・補完に現れます。全プロジェクトで使う場合は `~/.xharness/commands/` にコピーします。同名なら信頼済みプロジェクトの定義が優先されます。どちらにも既存の定義があれば、内容を比較してから統合してください。

例：`/commit 関連テストの結果も記載する`、`/pr 比較先はmain`。`$ARGUMENTS` は本文へ一度だけ置換され、本文が通常のuserメッセージになります。追加条件は文章であり、コマンドを直接実行するマクロではありません。両サンプルは提案までにとどめ、実行・公開は確認後の別の入力で扱います。新しいsystem指示や専用ツールは追加しません。

これらのコマンドを実際のアプリで送信すると通常のモデル通信が発生します。この作業では送信・認証・Git公開操作を行わず、設定解析と展開、モックのBashによる条件・引用・承認拒否のみを検証しました。
