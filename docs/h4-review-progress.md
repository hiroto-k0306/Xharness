## 依存とAPIの承認事項（指摘4・2026-10-03承認済み）

- 既存の `ignore@7.0.11` はNode代替検索で `.gitignore` のコメント・否定・ディレクトリ・ネストしたルールを扱うために追加した。AGENTS.mdの設計変更の事前確認を経ていなかったため、理由と代替案を記録して承認を求めた。実装・package.jsonを維持する。
- 採用理由：Grep / GlobのNode代替でも `.gitignore` を尊重するH2の指定を満たす。単純なglob変換だけでは否定と親ディレクトリ除外などを正しく扱えない。MIT、純JavaScript。[公式リポジトリ](https://github.com/kaelzhang/node-ignore)。
- 代替案：自前のgitignore解釈（依存は減るが互換性・保守・試験の負担が増える）、Gitのcheck-ignore呼び出し（Git無しの環境診断・代替検索の目的と衝突する）、他のgitignore対応ライブラリ（別の依存承認と比較検証が必要）。通常のminimatchだけではgitignoreの解釈を置換できない。
- `node:path.matchesGlob` はGlobパターンの照合に使う。Node 22.5.0以降で利用でき、22.20.0以降はstable。古いNode 22ではexperimentalのため、警告がstderrへ出る可能性がある。[Node公式資料](https://nodejs.org/api/path.html#pathmatchesglobpath-pattern)。
- 実測：この作業のNode 22.23.3で `matchesGlob('a.txt', '*.txt')` を呼んだ際、ExperimentalWarningは出なかった。Node代替のツールは子プロセスを呼ばず、結果本文へstderrを結合しない。古いランタイムではheadlessのstderrやアプリの実行ログに警告が混ざり得る。警告を全体で抑制する変更は加えていない。
- 代替案：glob照合の自前実装（対応パターンを狭めるか、多くの互換試験が必要）、minimatch等の安定したライブラリ（追加依存の承認が必要）。現状維持を承認する場合は、配布・headlessの実行環境をNode 22.20以降で確認する運用を推奨する。Nodeの最低バージョン設定は今回変更していない。
- 2026-10-03、人間が「両方の採用を承認する」と回答。DESIGN.md §15-Bへ反映した。
- Electron内のNode v24.21.0でも `matchesGlob('a.txt', '*.txt')` のstdoutは `v24.21.0 true`、stderrは空だった。古いNode 22では未実測。

## 修正内容

1. `purge`：厳格な `turns()` を使わず、期限判定に必要なcreatedAtだけ読む。不正な名前・JSON・日時、リンク、アクセス不能な記録は保持して他の記録へ進む。起動時は明示的に実行し、通常は同じ保存先について1時間に1回に制限する。別セッションの不正JSON・不正フォルダ・リンクがあっても、起動・Writeのターン・/undoが完了する統合テストを追加した。
2. Windows子孫：既存コードにはすでにKILL_ON_JOB_CLOSEのJob Objectがあり、taskkillのみではなかった。修正前の自然終了テストはこの環境の単独実行では成功したため、レビュー時の失敗原因を完全には再現できていない。Jobを閉じる際の終了開始と、子孫が実際に終了する時点の差を抑えるため、自然終了前にJob内の子孫を列挙・終了・待機する。終了中に生まれた子孫も再列挙する。PIDだけでなく同じJobのメンバーかを確認する。強制停止は従来のJob終了管理を維持する。[WindowsのJob Object仕様](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。
3. `BackgroundOutput`：既に返した先頭・末尾は残さず、中略した未読部分を新規出力より先に読み出す。1 MiB制限ではUTF-8の文字境界まで進め、30,000文字の表示境界でもサロゲートを分断しない。未読出力の順序と日本語・絵文字を検証した。
4. rg無し：検索対象がワークスペース自身でも親のignore規則をファイルシステムの根まで読んでおり、リポジトリ内の `spike/.out` に作ったテスト用ワークスペース全体が除外されていた。Node検索で読む祖先規則をワークスペース内に限定した。rg専用テストは `it.skipIf`、Node代替のGrep/GlobはPATHからCLIを除いて独立して検証する。
5. タイムアウト：headless-replayはTypeScript付きNode子プロセス起動を伴うため、テストを30秒へ拡張した。CLIログインの検出テストは15秒へ拡張した（CLI起動処理の制限は変更しない）。全体テストのrg無し初回で認証の模擬イベント待機が既存の1秒を超えたため、該当2テストの待機を5秒、テスト上限を10秒へ拡張した。実認証やプロバイダ通信は行っていない。
6. コードのみの/undo：復元できたファイルだけ、最新の該当記録のafterを復元後のbeforeに更新する。繰り返した/undoで自分自身の復元が競合にならない。スキップしたファイルは更新しない。
7. 会話マーカー：keepが履歴件数を超える等の不正値なら、履歴を保持して固定の日本語警告を記録する。セッション読込時にアプリの警告へ渡す。履歴本文・パスなどを警告へ含めない。
8. 原子的復元：対象と同じフォルダの一時ファイルに書き、対象が変わっていないか再確認してrenameする。一時ファイルはfinallyで削除する。
9. tool_result：構造化エラーのJSONと同じ本文、および同じエラーメッセージの本文先頭を重複させない。別の補足内容は残す。
10. 環境診断：書き込みプローブを廃止し、`access(W_OK)` による変更を伴わない権限確認へ置換した。ディレクトリの内容とmtimeが変わらないことを検証した。これは書込可能性の目安であり、WindowsのACL・ボリューム状態等による実際の書込成功を保証しない。実書込時のエラー処理は維持する。

## 同じ失敗3回の判定案（指摘10・実装しない）

- 現行H2は「同じツール・同じ種別の失敗が同一ターンで3回続いたら停止」。別パス・別パターンでも同じ種別なら数えるため、正常な探索でnot_found / invalid_argsが3回出ると止まる。成功や種別変更でそのツールのカウントを戻す。他ツールの呼び出しではそのツールのカウントを戻さない。
- 推奨案：not_found / invalid_argsだけ「ツール名・種別・正規化した引数のSHA-256」が同じ場合に連続回数を数える。キーの順序を揃えたJSONをハッシュ化し、生の引数をログや診断メッセージに保存しない。引数変更・成功・種別変更で回数をリセットする。
- missing_cli / denied / timeout / failedは、引数を変えても環境・権限・実行基盤の問題が続く可能性があるため、現在のツール名・種別の判定を維持する。abortedは3回停止の対象外を維持する。
- 影響：別の場所を探す正常な探索を止めにくくなる一方、無意味に引数を変え続けるループはこの判定では止められなくなる。既存の連続5失敗停止・100ステップ上限・workflow_stalledは維持する。全種別を引数単位にする案より、この限定案を推奨する。
- DESIGN.md §26.1 H2の明示条件が変わるため、別途人間の承認と設計更新が必要。今回はcountErrorの判定を変更しない。
