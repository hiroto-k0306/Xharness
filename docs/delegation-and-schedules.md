# 子の結果を使う再委託と、起動中の予約（L3・L4）

## L3：前の子を選んで新しく委託する

親エージェントは `TaskHistory({})` で、この親セッションで完了・質問待ちになった子のID、名前、最終結果と質問を確認できます。次の `Task` へ `previousChildId` を指定すると、選んだ子の情報だけが新しい依頼文の末尾に参考データとして添えられます。

```json
{
  "agent": "explorer",
  "description": "回答を踏まえて再調査",
  "prompt": "前の質問への回答はAです。その条件で再調査してください。",
  "previousChildId": "TaskHistoryに表示されたchildId"
}
```

新しい子の会話はこの依頼1件から始まり、前の会話、system、ツール、権限承認を復元しません。`background: true` でも使え、通常どおりTaskOutputで新しい結果を取得します。前の結果は命令・権限として扱わず、必要な操作の権限を新しい子が確認します。

同じ親の直近32件だけをメモリに保持し、最終結果6,000文字と直近最大5質問の合計2,000文字までです。秘密マスクを適用してから保持します。失敗・中断・実行中の子、別親のID、期限切れのIDは指定できません。親のターンが変わっても同じruntimeがある間は選べますが、会話を閉じるかアプリを終了するとこの選択用一覧は消えます。既存の保存済み子履歴は削除しませんが、起動時にその履歴から自動復元はしません。新しいTaskのprompt本体は64,000文字までです。

利用者は親へ「TaskHistoryのこのchildIdを使って、質問への回答を添えて再委託して」と指示できます。TaskHistory・Task自体の利用は通常の親モデルの通信を伴います。この作業では実モデルに送信していません。

## L4：入力欄から登録する予約・イベント待ち

通常のアプリ入力欄で以下を送信できます。補完にも `/schedule` と `/signal` が表示されます。登録・一覧・取消・イベント通知はローカルで処理し、モデルへ送りません。登録の成功・ID・制限は会話欄に表示します。

```text
/schedule after 300 変更差分とテスト結果を確認して
/schedule every 600 3 作業状況を確認して
/schedule idle 今の作業が正常終了したら結果を整理して
/schedule event ready 追加資料を踏まえて調査して
/signal ready
/schedule list
/schedule cancel <予約ID>
/schedule cancel all
/schedule help
```

- `after`：1〜604,800秒後に1回。時間は登録からの経過秒数です。
- `every`：60〜604,800秒間隔、1〜20回。最初も指定秒数後に発火します。次の予定は前回の送信開始後から間隔を取り、実行中は待ちます。遅れた回をまとめて実行しません。
- `idle`：登録後の同じ会話の次の正常終了（end_turn / workflow_complete / reported_done）後に1回。登録時点ですでにidleでも発火せず、手動圧縮の終了も対象外です。
- `event`：同じ会話で登録後に `/signal <名前>` が届くと1回。名前は英数字・underscore・hyphenの1〜64文字。登録前の通知は記憶しません。重複通知も同じ予約を再発火させません。

予約は1会話5件・アプリ20件まで。指示は4,000文字までの普通の文章で、スラッシュコマンドを予約することはできません。空白は通常の区切りへまとめます。登録から7日を過ぎた予約は終了します。時計の変更・スリープで実行が遅れることがあります。約1秒ごとの確認で発火するため、秒単位の厳密な時刻は保証しません。

**発火時の送信は通常のモデル通信です。** 登録した会話の、その時点のモデル・権限モード・信頼確認・通信回数上限で実行します。実行中・承認待ちには重ねて送らず、idleになるまで待ちます。通常の送信が拒否された場合は予約を終了し、自動再試行しません。ターンが失敗・中断した場合は、その会話の残りの予約をすべて取り消します。ツールの実行は通常の権限確認に従い、予約が承認を代替することはありません。

停止ボタン／`/stop`、会話を閉じる・削除する操作、アプリ終了でその範囲の予約も取り消します。個別のcancelは未開始・送信準備中の予約を取り消します。すでにモデルの実行を開始した場合は停止ボタンで中断してください。

予約はメモリ上だけで、保存・復元しません。アプリを終了すると消え、アプリ停止中には動きません。再起動で自動のモデル通信や取り逃した予約の再実行は発生しません。OSサービス、バックグラウンド常駐、外部Webhook、ファイル監視、cron式・時刻指定、headless用の予約は今回追加していません。

新規テストはFakeProviderとモック・仮想時計だけを使い、子の質問／結果の引き継ぎ、秘密マスク、所有権、容量、予約の重複・停止・期限・上限、通常の権限拒否、通信上限、再起動時に実行しないことを確認しています。実モデル・実アプリの起動・インストール済みexeの確認は行っていません。
