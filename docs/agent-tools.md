# 停止・質問・子エージェント管理

2026-10-02 実装。Claude / Codex の両方で使える XHarness の共通ツール。

| ツール          | LLMが渡す引数                                            | 動作                                           |
| --------------- | -------------------------------------------------------- | ---------------------------------------------- |
| StopTask        | `{reason: "停止理由"}`                                   | 理由を表示して現在のターンを停止               |
| AskUserQuestion | `{question: "質問", options?: ["候補A", "候補B"]}`       | 質問を表示してユーザーの返答待ち               |
| Task            | `{description, prompt, agent, model?, background: true}` | 子をバックグラウンド起動し taskId を返す       |
| TaskList        | `{}`                                                     | 当該親ターンの子の一覧                         |
| TaskOutput      | `{taskId, wait?: true, timeoutSec?: 30}`                 | 状態・最終結果を取得。待機の最大値は60秒       |
| TaskStop        | `{taskId}`                                               | 指定した子のみ停止し、承認待ち・保存を片付ける |

ユーザーは通常の入力欄で依頼する。例えば「調査を子エージェントに任せて。状況を確認して」「その子エージェントだけ止めて」。LLMがツールを呼んだときに実行され、普通の文章にツール名が含まれるだけでは実行されない。

質問は会話欄に日本語で表示される。候補がある場合は番号が付き、入力欄から番号または文章で回答できる。返答するまで追加通信は発生しない。専用の回答ボタンは今回の範囲には含めない。

停止時もファイル変更と履歴を保持し、未実施レビューを完了にしない。同じLLM応答に StopTask / AskUserQuestion と別の操作がある場合は停止・質問を優先し、他の操作はキャンセルする。不正な引数はエラーとして返し、修正可能にする。

子の状態は `running`（実行中）、`done`（結果あり）、`stopped`（停止）、`awaiting_user`（ユーザー判断が必要）、`error`（失敗）。Agents欄でも停止・返答待ちを区別する。TaskOutput は最終結果・停止理由を返す機能で、途中の全文ストリームは既存の子の会話表示を使う。

同時実行3件、1ターンにつき32件まで。親が終了・停止すると残りの子も停止するため、必要な結果は親の終了前に回収する。次のターンや別の親では前のtaskIdを操作できない。子の質問を受けた親は AskUserQuestion でユーザーへ取り次ぎ、回答後は新しい Task で必要な情報を渡して再委託する。

従来の `Task` は background を省略すれば終了を待つ。worker の計画・worktree・レビュー・統合は従来のワークフローが管理し、この管理ツールの対象にはしない。

検証はFakeProviderとテスト用Providerで実施。停止後の通信抑止、同一応答内の副作用キャンセル、必須レビューの維持、返答後の再開、子の質問、個別停止、親停止、承認待ち解放、待機タイムアウト、並列起動した子の索引保存を確認した。全86ファイル・719テスト、typecheck、lint、Electron / headless build が成功。実Claude/Codex通信での新ツール呼び出しは未確認。
