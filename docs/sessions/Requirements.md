# 会話・作業場所・利用者操作の要件（Why）

基準: 2026-10-09、`0e5fa40da0d8bc39b71fb36b83cce82a8fe18087`。現行コード・直接テストを読み取った要求整理であり、この文書の作成でWindowsアプリや実モデルを再実行したものではない。

## 背景と目的

利用者は同じプロジェクトについて複数の会話を開き、質問、作業、結果確認を行う。会話の選択と作業場所の文字列だけを頼りに承認・保存・再開を判断すると、別会話の操作許可、削除後の履歴復活、未確定な外部処理の再実行が起こり得る。

会話と作業場所の所有を明確にし、GUIとheadlessで同じ保存・公式実行境界を使う。操作は利用者が読んで確認できる場所へ集め、記録は後から出典と欠測を確認できる形で保全する。旧履歴を読むことと、旧モデル経路を実行することを分ける。

## 関係者

| 関係者               | 必要とする結果                                                     |
| -------------------- | ------------------------------------------------------------------ |
| Windows上の利用者    | 選択中の会話と対象を確認し、チャットで承認・拒否・停止できること   |
| headless利用者       | 同じ公式経路を使い、実行の意思と終了状態が曖昧でないこと           |
| プロジェクトの保守者 | 既存変更と履歴が守られ、結果・レビュー・不確定状態を追跡できること |
| 開発・検証担当者     | fixture、保存済み実測、今回の検証範囲を区別して評価できること      |

## 利用者のニーズと意図

| 利用者のニーズ                                             | なぜ必要か                                           |
| ---------------------------------------------------------- | ---------------------------------------------------- |
| 複数の会話で、どのプロジェクトの話をしているか把握したい   | 同じ場所の作業でも会話の目的や責任範囲は異なるため   |
| 会話を読み終えても、必要な履歴を残したい                   | 閲覧を終えることと、記録を捨てる意思は異なるため     |
| アプリや端末の操作が重なっても、保存した記録を失いたくない | 後から説明・比較・復旧するための根拠が必要なため     |
| 中断後は実際に何が起きたか確認してから作業を続けたい       | 不確定な操作の繰り返しは、意図しない変更を生むため   |
| 作業の計画や操作を読んで、その依頼にだけ回答したい         | 会話の文脈を保って許可範囲を判断したいため           |
| チャットを主に使い、必要なときだけ詳細を調べたい           | 進行中の会話と長い診断記録の両方を扱うため           |
| 画面から離れていても、待機や終了を知って安全に戻りたい     | 通知によって作業内容が外部へ見えることは避けたいため |
| 端末経由でも、実行の意思と終了状態を明確にしたい           | 自動化した入力と人が与える許可を取り違えないため     |
| 過去の知見や結果を、内容と出典を見てから再利用したい       | 参考資料を現在の指示や権限と混同したくないため       |
| 過去の記録を読むために、新しいモデル処理を始めたくない     | 閲覧の目的は保存された事実の確認であるため           |
| 機能が廃止されても、自分の保存データは失いたくない         | 操作方法の変更と、データを廃棄する意思は異なるため   |

検証可能な要件の正本は [Spec §1](Spec.md#1-検証可能な要件)。この文書はその理由を説明し、APIや検証条件を定義しない。

## 前提と適用範囲

ローカルで管理する会話とプロジェクトを対象とし、desktopとheadlessのどちらから使っても同じ保存記録を理解できることを想定する。OSの管理者や任意の外部ツールによる変更まで管理する製品ではない。

旧版の会話と利用者データを保持しながら、現在の公式モデル経路を使う。過去の操作名や保存形式が残っていることから、その旧機能が現在も実行できると期待させない。

この文書群は会話への帰属、利用者操作、保存と参照を扱う。モデル選択、計画生成、sandbox、独立検証の実行条件は [workflow仕様](../workflow/Spec.md)、スキル実行は [skills仕様](../skills/Spec.md) を参照する。

## 非機能要件の意図

保存の整合性は、後から判断するための根拠を信頼できるようにするために必要である。失敗・破損・未確定を区別できれば、利用者は記録の限界を理解して次の行動を選べる。

プライバシーは、通知や記録共有のために、利用者が意図しない範囲へ作業内容が見えることを避けるために必要である。任意の秘密を完全に匿名化する保証ではなく、共有前に内容を確認できることも大切である。

操作性は、会話の文脈を保ちながら許可範囲を判断し、必要なときに詳細を読み、停止理由を理解できるようにするために必要である。具体的な表示、保存、期限、拒否条件はSpecに置く。
