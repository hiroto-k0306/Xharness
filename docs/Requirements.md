# XHarness の要求

## 背景と目的

XHarnessは、個人のWindows環境で、利用者が選んだ作業場所に対して質問・探索・実装・検証・レビューを進めるコーディング支援アプリです。公式Claude Agent SDKとCodex App Serverを用い、正規のサブスクリプション認証と利用枠の範囲で使うことを意図します。

利用者が同じ説明や障害修正を繰り返さずに作業を続けられること、実装と別会社のレビューを組み合わせられること、変更内容・確認結果・未確認事項を根拠とともに判断できることを目的とします。最終的な同意と判断は利用者に残します。

## ステークホルダーのニーズ

| 当事者             | 必要な価値・意図                                                                                   |
| ------------------ | -------------------------------------------------------------------------------------------------- |
| 個人利用者         | チャットを中心に依頼し、計画や操作を理解して承認できる。既存の作業・会話・資料を保護して続けられる |
| 開発・保守担当     | 要求、検証可能な要件、具体的な振る舞い、設計、検証結果を追跡し、旧版を現行仕様と取り違えない       |
| 検証・レビュー担当 | 実装者の報告、独立検証、過去の実機結果、現在の未確認事項を区別して評価できる                       |

## 前提条件とスコープ

対象はXHarnessのWindows desktopと共通サービスを使うheadlessです。一般的なPC全体の管理、OS設定の変更、認証基盤の代替、他社アプリへの汎用操作権限の提供はこのシステムの目的に含めません。

公式runtime、モデルカタログ、利用可能性、Node・Git・PowerShell等は外部依存です。過去に動いた版が、将来の版・別PC・別配布形態でも動くと仮定しません。旧実行器の記録とユーザーデータは保全対象であり、旧機能の再有効化を要求するものではありません。

スコープ階層はシステム⊃サブシステム⊃機能です。現在は共通main/rendererとサービスの連携が強いため、別のサブシステム文書層を作らず、機能単位の「作業実行」「会話・保存」「スキル」と横断事項へ分けます。

## 非機能の要求概要

利用者の作業と保存記録を保全し、会話・作業場所の所有境界を維持します。資格情報・秘密・非公開思考を必要以上に扱わず、承認の範囲を越えて実行しません。利用枠と費用を尊重し、モデルの選択や検証結果を透明にします。曖昧な成功表示や根拠のない所要時間予測を避け、未実装と未検証を区別します。

ここはWhyの正本です。数値上限、API、状態、受入条件は[全体Spec](Spec.md)と各機能Specで定めます。実装上の構造はdesign、実測の結果はreportを参照します。
