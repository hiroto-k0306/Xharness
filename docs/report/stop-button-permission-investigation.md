# 停止ボタンとインストール拒否の調査

2026-10-04。`codex/windows-shell-session-delete`で追加対応。

- 停止ボタンを入力行の右端へ移動。丸の中に四角の記号を表示する。
  狭い画面でも入力行右端に置き、読み上げ名は「停止」、説明は「停止（Esc）」。
  権限確認待ちでも停止ボタンを利用できる既存動作は維持する。
- 利用者の最新レシートを読み取り専用で確認。インストールそのものではなく、
  `Get-Command winget, scoop, choco, rg ... | Select-Object Name, Source`
  が2回、実行前のgateで拒否されている。OS側のインストールエラーではない。
  記録されたセッションモードはacceptEdits、readOnlyはfalse。
- workflowのclassify/plan段階は、セッションがacceptEditsでもBashをplanの
  判定に通す。パイプを含むこのコマンドはそこでdenyとなり、確認画面には進まない。
  セッションの保存履歴だけで、当時の段階や設定の全てを確定したわけではないが、
  コード上の該当拒否経路と一致する。モックの回帰テストでplanではdeny、
  acceptEditsの通常判定ではaskを確認する。
- チャットの「許可」は、ネイティブの権限応答やワークフロー段階の移行とは別。
  調査時点ではインストールは一律禁止されていない。モデルがSubmitPlanで承認を得るか、
  小規模作業で適切ならSkipPlanでimplementへ移り、Bashの実行確認を受ける必要がある。
- gate拒否時の本文が「ユーザーに拒否」と断定していたため、ユーザー拒否・
  権限ルール・段階制限の可能性を示す文言に変更。
  同じ操作を再試行する前に原因を確認するようツール結果に含める。
  この文言修正だけでは権限判定、承認要件、システム権限は変更しない。
- 実モデル・認証通信、インストールコマンドは実行しない。
