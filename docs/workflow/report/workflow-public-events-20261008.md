## 変更

各request IDの入力・構造化応答に加え、公開された途中応答、ツール要求・結果、開始・終了を受信順で保存する。LoopFlow・詳細パネル・HTMLに「公開イベントの時系列」を折りたたみ表示し、LLM、ツール、ハーネス、公式基盤を色分けする。許可・拒否はハーネスの承認判断として表示する。

Claudeはassistant text/tool_use、user tool_result、PostToolUse/Failure、resultから選別する。モデルとparent_tool_use_idを保持し、明示的なnull（主系列）と未提供を区別する。hookに親IDがなく、後続メッセージで提供された場合は重複を増やさず追記する。失敗hookのエラー本文は保存せず、本文欠測を表示する。

Codexは既存のthread/turn照合後、agentMessage、commandExecution、fileChangeとturn開始・終了から選別する。思考・analysis・アカウント通知を除外する。item完了と最終turn内itemsの重複を除く。終了状態や出力が未知なら成功を補完しない。

本文は既存の秘密値マスクを通し、思考・画像・音声本体を除去する。各本文4,000文字、1呼出128イベント・64,000 UTF-8バイトを上限として省略を明示する。バイト上限は記録するイベントのJSON表現に適用し、workflow全体のファイルサイズを表すものではない。保存は既存の直列化経路を利用し、失敗時にphaseを停止する。モデルの再送や追加呼出は行わない。
