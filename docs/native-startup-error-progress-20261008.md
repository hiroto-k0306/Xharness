## 自動追従についての提案（未実装・未採用）

ユーザー案は実現可能。ただし「固定先の中身を実行中に上書きする」「最新版なら互換性未確認でも必ず適用する」は採用しない方がよい。

### Claude

- 管理用の親フォルダーを固定し、その下にバージョン別のSDK・SDK対応CLI・必要な依存一式を配置する。既存のclaude.exeだけを更新してSDKと組み合わせる方式にはしない。
- XHarness稼働中に24時間あたり1回確認する。アプリが閉じている間は確認せず、次回起動時に期限を確認する。更新確認はパッケージ情報の取得で、モデル送信・認証更新は不要。
- 更新候補を別の一時配置先へ取得し、公式の取得元・integrity・OS/CPU・依存関係・SDKの必須機能を検証する。利用枠確認に使うexperimentalメソッド等が消えた場合は未対応として停止し、API課金や旧HTTPへ戻さない。
- 導入完了後に採用版を指す小さな管理ファイルを原子的に切り替える。実行中のタスクは開始時の版を固定し、旧版は利用終了まで残す。更新確認・配置にはプロセス間ロックを置く。
- SDKはJavaScriptモジュールでもあり、現在はclaude.tsから静的importされている。ディスク上を更新するだけでは起動中プロセスのSDKは切り替わらない。外部の版別SDKをタスク単位で読み込む専用worker/子プロセスと、XHarness側の固定した通信境界を用意する必要がある。
- 対応可能な版の範囲と更新チャネルを定義する。未知の非互換版は自動採用しない。モデル通信を伴う互換試験は日次確認に組み込まない。画面に使用版・確認日時・候補版・更新失敗を表示する。

現在のpackage.jsonとSDKのpackage metadataでは、Agent SDKは0.3.290固定、対応するnativeパッケージも0.3.290でclaudeCodeVersionは2.1.290。PCに別途導入されたClaude Code 2.1.177とは別の配布単位。新方式ではSDKそのものの解決・ロード方法の変更が必要となる。

### Codex

- 通常モードは公式デスクトップアプリが現在使用するCLI一式を解決し、タスク開始時に実パス・版・必要なhelperを確認して固定する。フォルダー名の辞書順やmtimeだけを根拠に最新とみなさない。
- 実行準備失敗のときは具体的な理由を出し、利用者が別の公式CLI一式のフォルダーを指定できるようにする。失敗した処理を新CLIで自動再送しない。
- 指定フォルダーのoverrideが有効な間はその版を固定し、「同梱版へ自動追従に戻す」を明示的に操作できるようにする。新しい同梱版を検出してもoverrideを勝手に解除しない。
- 自動モードはアプリ更新へ追従可能だが、override中の自動追従は停止する。この違いを設定・画面に明記する。
- 既存設定の絶対exeパスは固定指定として引き継ぐ。既存利用者の設定を無断で自動モードへ変更しない。資格情報の保存先・認証経路は公式CLIのものを維持する。

この方式ではClaudeもCodexもハーネスの再配布に依存しない更新が可能になるが、現在のSPECとは配置・ロード・更新仕様が変わる。本依頼では妥当性の質問として検討し、更新機能自体の実装前に採用方針を確定する。
