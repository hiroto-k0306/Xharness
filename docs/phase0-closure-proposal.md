# Phase 0 完了に向けた確認案

承認済み（ユーザー、2026-10-01）: 公式 CLI による更新試験を許可、Ultra を保留し通常 effort で進める。最終結果は [phase0-findings.md](phase0-findings.md)。

## 期限切れ時の対処

DESIGN.md §14 の方針どおり、XHarness は refresh API を直接呼ばない。
期限切れや認証エラーでは推論の再試行を止め、公式 CLI で認証を更新し、資格情報ファイルを読み直してから最小リクエストを1回確認する。
公式 CLI は書き換えを行う可能性があるため、AGENTS.md の「Phase 0 では書き換えない」との例外を人間に確認する。
試験では CLI を短い ping で各1回だけ実行し、前後の秘密値はメモリで比較する。ファイルに保存するのは変化の有無・期限・終了状態のみ。
CLI の標準出力・エラーは生で表示・保存しない。直接の refresh、期限切れの偽造、既存資格情報の編集はしない。
期限が遠く CLI が更新しなかった場合は、その事実と更新未実測を記録し、対処方針の確定と区別する。

## Ultra の扱い

X4 / X5 と調査した公式ソースから、Ultra は通常推論の effort に加えて自動委譲を伴う UI 選択である。
初期カタログの `ultra: ultra` を削除し、Phase 1 の API effort は low / medium / high / xhigh / max の範囲にする案。
Ultra は委譲動作も含めて設計が決まるまで選択肢として有効化しない。単純な wire 値として扱わない。
実測済み値と、モデル一覧に掲載されているだけの値は引き続き区別する。

## 完了判定

手順書の6つの完了条件に照合する。任意のキャッシュ試験、全ヘッダの省略試験、全モデルと effort の組み合わせ、自然に発生しなかった429は完了必須に追加しない。
未実測の事項は調査記録に明記する。未完了を完了と記載しない。
