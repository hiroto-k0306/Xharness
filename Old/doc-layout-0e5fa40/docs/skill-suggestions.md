# 依頼に関連するスキル候補

現行仕様はSPEC.md §9。`feat/skills-manager`の`6f6d9ce0b4588cb0f03b12c1f22073244f925cde`を開始点に、管理画面へ保守的な候補提示を追加した。既存の一覧検索は部分文字列による絞込みとして残す。履歴・メモリ検索は各データの一致検索なので再利用対象にはせず、ファイル読取・索引・モデル通信は追加しない。

## 操作

1. 会話入力欄に依頼を書き、送信前に「スキル管理」を開く。「一覧を取得・更新」を押し、既存の許可確認に応答する。候補はこの許可済み一覧を使う。候補だけのために別途ファイルを読まない。
2. 「依頼内容・明示キーワード」に内容を入力するか、「入力中の依頼を使う（先頭500文字）」で会話入力欄の文をコピーする。会話入力欄の文は変更・送信せず、候補用の文もローカルなUI状態だけに保つ。
3. 名前・説明の語が一致した候補と短い理由を確認する。最大3件で、それ以上は省略件数を表示する。0件でも無関係な候補を埋めない。「候補を選択」で既存の詳細欄へ進む。この操作だけでは本文読取もモデル通信も始まらない。
4. 出典・hashを確認し、「この版をプレビュー」で既存許可を経て本文を確認する。「会話でこの版を読み込む」は通常のモデル実行と許可確認を伴い、成功した実tool receiptの版だけ読込済みとなる。候補そのものは品質の証明でも権限の付与でもない。

入力変更と一覧更新開始時は、古い選択とプレビューを解除する。更新の拒否・取消・失敗やプレビュー失敗後は、一覧の再取得が成功するまで候補を隠す。取得後にファイルが変わる可能性はあり、実プレビュー／loadのhash照合で拒否される。再選択が必要で、自動で新版を読むことはしない。既存会話に成功済みの旧版が残る場合の扱いは管理画面と同じ。

## 選定規則と限界

- Unicode NFKC・小文字化、`_`／`-`の区切り、標準`Intl.Segmenter("ja")`による語分割を使う。英数字3文字以上、その他2文字以上、1語64文字以内。一般的な依頼語（please、help、してください、作業等）は除く。
- 依頼の先頭500文字から最大16種類の語を比較。取得済み一覧の最大50件について名前64文字・説明1,024文字だけを使う。語の繰返しでは加点しない。名前で一致すれば3点、名前で一致しない説明の一致は1点。同点はsource順。名前・説明中の命令文も単なる文字データで、実行・権限変更はしない。
- 簡易関連度は上の語一致の加点値で、成功確率・品質スコアではない。最大3候補、説明は各160文字、理由は最大3件・一致語の表示は各32文字。依頼／語数等の上限や候補省略を表示する。
- **最適性や品質は保証しない。** 同義語・英語の活用形・意味・否定・タスク難度は推論しない。短い略語や日本語の分割差で取りこぼし、同じ語が別の意味で使われた場合に誤一致がありうる。理由を確認し、具体的なキーワードで再検索するか通常一覧から選ぶ。
- 本文、付属script、追加frontmatter、sourceのパス語は候補選定に使わない。本文の命令を選定指示として実行しない。第三者取得・global探索・自動実行・自動選択・自動ルーティング・本番A/Bは行わない。

既存permission／workspace境界／予算／秘密フィルターを通った一覧だけを使う。本文読取と会話loadは既存trace／receiptにsource・hashと結果を残す。候補の計算・選択自体はモデル通信や新しいタスク品質の記録を生成しない。headlessの既存ツールは変更しない。

## オフライン再実行

```powershell
.\scripts\pnpm.ps1 test src/shared/skill-suggestions.test.ts src/main/session/skill-ui.test.ts
.\scripts\pnpm.ps1 test
.\scripts\pnpm.ps1 typecheck
.\scripts\pnpm.ps1 lint
.\scripts\pnpm.ps1 format:check
.\scripts\pnpm.ps1 test:gui
.\scripts\pnpm.ps1 build:headless
```

日本語・英語・誤一致・0件・多数件・入力変更・古い候補・拒否・取消・連打と既存loadへの遷移を独自fixture／FakeProviderで確認する。実プロバイダ・認証CLI・サブスク枠は使わない。検証記録は[こちら](skill-suggestions-validation-20261005.md)。
